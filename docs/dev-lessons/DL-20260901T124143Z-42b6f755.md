# NAVER API HUB 검색 응답은 JSON 본문을 text/plain으로 반환한다

## 적용 범위와 비적용 조건

NAVER API HUB /search/v1/* 응답을 파싱하는 모든 코드. Search Trend(POST /search-trend/v1/search)는 application/json으로 응답하므로 비적용.

## 관측 사실과 영향

2026-09-01 실호출에서 blog/cafearticle/kin/webkr/news/errata 전부 HTTP 200이지만 Content-Type이 text/plain;charset=UTF-8이었다. content-type 기반 분기는 본문을 버려 total/items가 비어 보였고 검증 스크립트가 전 채널 FAIL로 오판했다.

## 근본 원인·기여 요인·근거

HUB 게이트웨이가 검색 응답의 Content-Type 헤더를 JSON으로 설정하지 않음(공식 문서에 미기재). 클라이언트가 헤더를 신뢰하고 본문 파싱을 생략한 것이 기여 요인.

## 해결과 예방 control

HUB 응답은 content-type과 무관하게 본문 JSON 파싱을 시도하고 실패 시 schema 오류로 분류한다. docs/10에 주의사항 명문화, 클라이언트는 r.json() 직접 호출.

## 검증

tests/unit/test_hub_client.py::test_search_parses_text_plain_json_body 회귀 테스트가 text/plain 헤더 fixture로 통과. scripts/verify_api_hub.py --all 재실행 시 6채널 PASS.

## 발생 정보

2026-09-01 Phase 2 외부 API 검증 중 발견. 영향: 검증 스크립트 오판(수 분 내 수정), 데이터 손실 없음.

## 검토와 예외

HUB가 헤더를 수정하면 이 회귀 테스트는 계속 유효(본문 파싱은 헤더와 무관). 예외 없음.
