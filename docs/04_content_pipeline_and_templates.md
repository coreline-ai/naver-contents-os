# 04. 콘텐츠 생성 파이프라인과 템플릿 전략

## 1) 기존 고정 템플릿
README 기준 고정 형식:
- 제목: 25~35자
- 핵심 키워드 3개 포함
- 본문: 2,500자 이상
- 구조: `공감 -> 정보 -> 경험 -> 마무리`

단일 템플릿은 초보형 운영엔 사용 가능하지만, 실제 서비스에서는 한계가 큼.

## 2) 권장: 유형별 템플릿 분리

| 유형 | 제안 구조 |
|---|---|
| HOWTO | 문제 → 준비 → 단계 → 오류 → FAQ |
| POLICY | 결론 → 조건 → 예외 → 신청방법 → 주의사항 |
| COMPARISON | 요약 → A → B → 표 → 추천 대상 |
| REVIEW | 사용배경 → 경험 → 장점 → 단점 → 결론 |
| HOMEFEED | Hook → 핵심 사실 → 이야기 → 추가정보 |
| PRODUCT | 문제 → 제품 → 장단점 → 대안 → 구매 체크 |
| NEWS | 사건 → 핵심 사실 → 배경 → 영향 |
| SERIES | 앞편 연결 → 이번 질문 → 답 → 다음편 |

즉 `BlogType` 수준의 구조화가 필요.

## 3) Screenshot 기반 변환
최대 100장 입력, 이미지 속 텍스트 분석 + 중복 제거 + 시간/단계 정렬 + 각 이미지 설명 연결 → 블로그 원고 생성.

이 부분은 제공된 텍스트 분석/요약 워크플로와 잘 맞음.

## 4) 이미지 전략
현재는 부족할 때 Unsplash 보강.
개선 제안:
- 정보형 글에서는 다이어그램/인포그래픽을 자동 생성해 문맥 정합성 향상
- 스크린샷 기반 서술일 때는 유사성 높은 시각자료를 우선 배치

## 5) 썸네일
`HTML/CSS → Screenshot` 방식의 1000×1000 생성은 템플릿화가 쉬워
정보형/뉴스형/비교형/제품형/강조형 등으로 재활용 가치 큼.

## 6) CTA 확장성
현재 단일 CTA 변수(`CTA_ENABLED/LINK/TEXT`) 대비:
- `NONE`, `RELATED_POST`, `NEXT_SERIES`, `SHOPPING_CONNECT`, `PREMIUM_CONTENT`, `EXTERNAL_CHANNEL`
로 일반화하면 콘텐츠형태별 후킹 전략 강화 가능.
