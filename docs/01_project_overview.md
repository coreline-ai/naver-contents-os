# 01. 프로젝트 개요 및 핵심 성격

## 한눈에 보는 결론
- `kyoung-young/naver-keyword-tool`은 **키워드 분석 엔진**에 가까움.
- `choigpt-ai/naver-blog-automation`은 **콘텐츠 기획→작성→이미지/썸네일→네이버 임시저장**까지 이어지는 **제작·작성 자동화 파이프라인**.
- 즉 양쪽은 대체재가 아니라 **보완재**.
- 최종 제품은 두 저장소를 그대로 합치는 것이 아니라, **API 수집·점수화·브라우저 파서·SmartEditor 어댑터를 분리해 재조립하는 로컬 우선 Content OS**가 적합함.

## V1의 실제 외부 의존성

| 의존성 | 필요도 | 역할 |
|---|---:|---|
| NAVER API HUB | 필수 | 블로그·카페·지식iN·웹·뉴스 검색, 검색어 트렌드 |
| NAVER SearchAd | 필수 | PC/모바일 월간 검색량, 연관 키워드, 광고 경쟁 지표 |
| Browser DOM | 필수 | 현재 SERP, 블로그 공개 정보, SmartEditor 조작 |
| 외부 LLM API | 선택 | 글 생성·요약·분류. 로컬 LLM으로 대체 가능 |
| 네이버 로그인 API | V1 불필요 | 브라우저의 기존 네이버 로그인 세션을 사용 |
| 공개 블로그 글쓰기 API | 사용하지 않음 | 로그인된 SmartEditor에 임시저장하는 방식 사용 |

상세 발급 절차와 최신 비용 정책은 [10_api_and_account_setup.md](./10_api_and_account_setup.md)를 기준으로 합니다.

## 파이프라인 요약
붙여넣은 분석 텍스트 기준 전체 흐름:

1. 스레드 / 메모 / 스크린샷 수집
2. 내용 분석
3. 키워드 후보 생성
4. SearchAd 검색량 + 블로그 문서수 조회
5. 골든 키워드 3개 선별
6. LLM 집필
7. 제목+본문(최소 2,500자) 생성
8. 스크린샷/Unsplash 이미지 배치
9. 1000×1000 썸네일 생성
10. 로컬 Chrome 실행
11. SmartEditor ONE 조작
12. 제목/본문/이미지/태그 입력
13. 임시저장
14. 사람 검토 후 발행

## 중요한 설계 판단
- 완전 자동 발행 대신 **임시저장까지만** 수행.
- 최종 공개 여부는 사람이 결정(안전성·품질 통제 측면에서 바람직).
- 확장 프로그램에는 API Secret을 넣지 않고 `127.0.0.1`의 Local Core만 Secret을 사용.
- 검색량, 트렌드, 검색 문서 수, 공개 DOM 정보는 서로 의미가 다르므로 하나의 수치처럼 표시하지 않고 출처를 함께 저장.
- V1은 키워드 발굴→경쟁 분석→콘텐츠 기획→초안/임시저장까지만 포함하며, 자동 공개·다계정·SaaS는 제외.
