# SmartEditor 자동화는 브라우저 기본 readiness·editability·저장 시점 가정을 사용하지 않는다

## 적용 범위와 비적용 조건

NAVER SmartEditor ONE의 로딩, 제목·본문 입력, 자동저장과 명시적 임시저장 성공 판정에 적용한다. 일반 HTML input·textarea 기반 편집기에는 그대로 적용하지 않는다.

## 관측 사실과 영향

실브라우저에서 DOMContentLoaded 직후에는 글 로딩 shell만 보였고 편집 canvas가 아직 없었다. canvas가 나타난 뒤에도 제목·본문 paragraph는 contenteditable 속성을 노출하지 않았으며, 본문 입력 중 자동저장이 먼저 실행되어 최종 저장 버튼 직전의 저장 개수가 이미 증가했다. 기존 구현은 health check와 저장 성공을 오판해 안전하게 중단했지만 정상 임시저장을 실패로 기록했다.

## 근본 원인·기여 요인·근거

SmartEditor가 비동기 canvas mount, custom caret paragraph, 입력 중 서버 자동저장을 사용한다. 브라우저의 DOMContentLoaded와 locator.is_editable을 제품 준비·편집 가능 상태로 간주하고, persistence baseline을 최종 저장 직전에 수집한 설계가 실제 편집기 상태 모델과 맞지 않았다.

## 해결과 예방 control

실제 editor root가 보일 때까지 대기하고, custom caret fallback은 SmartEditor 제목·본문 paragraph selector로만 제한한다. 입력은 focus 후 page keyboard event로 전달한다. 저장 개수·상태 baseline은 자동저장이 시작되기 전 prepare_editor 단계에서 수집하고, 최종 성공은 완료 알림과 baseline 대비 persistent state를 함께 확인한다. 해시형 CSS module class는 안정적인 prefix selector를 병행한다.

## 검증

tests/unit/test_publisher.py에 editor root 대기, 태그 없는 health path, 실 DOM 저장 신호 selector, 입력 중 자동저장 이전 baseline 비교 회귀 테스트를 추가했다. 전체 non-live Python 186개와 Extension 47개가 통과했고 실브라우저에서 임시저장 완료 알림과 저장 개수 증가를 확인했다.

## 발생 정보

2026-09-03 Phase 7 실브라우저 인수 중 발견했다. 로그인 이후 health check와 저장 성공 판정에서 반복 재현됐으며 공개 발행은 발생하지 않았다.

## 검토와 예외

SmartEditor DOM과 CSS module hash는 다시 바뀔 수 있으므로 실패 evidence가 있을 때만 중앙 selector registry를 보정한다. 완료 알림 하나만으로 성공 처리하거나 공개 버튼을 자동 조작하는 예외는 허용하지 않는다.
