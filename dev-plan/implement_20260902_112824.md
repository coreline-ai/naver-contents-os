## 개발 목적

참조 오픈소스와 V1 문서에서 필수로 채택했지만 제품 화면 또는 사용자 흐름에 연결되지 않은 P0/P1 항목을 구현한다. 연관 키워드·트렌드·검색 근거를 사이드패널에 표시하고, 생성·수정한 동일 Draft를 SmartEditor 임시저장 Job으로 연결하며, SERP 판별·Opportunity Score 신뢰도·외부 API 호출 제한·SmartEditor 저장 증거를 안정화한다.

## 개발 범위

- 연관 키워드의 PC·모바일·합계 검색량, 모바일 비중, 광고 경쟁도, 결측/마스킹, 재분석 action을 사이드패널에 표시한다.
- Search Trend, keyword cluster, API HUB 상위 결과, Browser SERP 순위·광고 여부·수집 출처를 사이드패널에 표시한다.
- 알 수 없는 SERP DOM과 실제 빈 결과를 구분하고 혼합 레이아웃 결과를 중복 없이 수집한다.
- Opportunity Score에 coverage, 사용 가능 구성요소 수, confidence를 추가하고 UI에서 점수와 함께 표시한다.
- Draft 조회·편집·새 버전 저장을 사이드패널에 연결한다.
- 사이드패널에서 선택·수정한 동일 `draft_id`의 최신 버전으로 SmartEditor 임시저장 Job을 시작하고 상태를 조회한다.
- SmartEditor 임시저장 성공을 독립적인 두 신호로 확인하고 실패 시 URL·screenshot·DOM 증거 경로를 Job 이력에 남긴다.
- Provider 호출에 일간 한도, RPS pacing, `Retry-After`, 실제 전송 시도 기준의 원자적 사용량 예약을 추가한다.

## 문서 기반 제약 사항

- API Secret은 Local Core 밖으로 보내지 않고 Extension에는 Local Core token만 저장한다.
- 결측과 SearchAd `< 10` 마스킹은 0으로 표시하지 않는다.
- Trend `ratio`는 절대 검색량이 아닌 상대값으로 표시한다.
- Browser SERP와 API HUB 결과를 같은 출처로 오인하지 않게 분리한다.
- Publisher는 기존 Draft 최신 버전만 사용하며 새 분석·새 Draft를 암묵적으로 생성하지 않는다.
- Publisher endpoint는 Health Check 전체 통과 후 임시저장까지만 수행하며 공개 발행 코드는 추가하지 않는다.
- 실브라우저 side effect는 자동 테스트와 이번 작업에서 실행하지 않는다.
- 일간·월간 한도는 외부 전송 전에 원자적으로 예약하고 cache hit는 사용량을 증가시키지 않는다.
