## 개발 목적

- 이미 구현된 키워드 분석 기능을 실제 콘텐츠 작성·검수·임시저장·발행 확인으로 연결한다.
- Extension을 닫거나 키워드를 바꾼 뒤에도 저장된 작업을 검색하고 안전하게 이어 쓸 수 있게 한다.
- Draft와 실제 공개 콘텐츠를 구분해 콘텐츠 공백·노후화·다음 작업 추천의 정확도를 높인다.
- 기존 snapshot을 근거 브리프와 검색 의도 보드로 재사용해 LLM 초안 품질과 기획 속도를 높인다.
- PC·모바일 검색량을 빠르게 이해할 수 있는 보조 시각화를 추가하되 결측·마스킹 데이터를 왜곡하지 않는다.

## 핵심 상태와 계약 결정

### Draft 작업 상태

- 사용자 상태: `editing`, `review_ready`, `archived`.
- 시스템 전달 상태: 최신 Publisher Job에서 `none`, `pending`, `draft_saved`, `failed`를 파생한다.
- 실제 공개 상태는 Draft 상태에 포함하지 않고 `PublishedContent` 존재 여부로 판정한다.
- 최신 수정 시각은 가장 최근 `DraftVersion.created_at`을 source of truth로 사용한다.

### 발행 콘텐츠 상태

- `published`: 사용자가 URL과 공개 사실을 확인해 등록한 상태.
- `stale`: 공개 후 설정된 기준일이 경과한 파생 상태이며 공개 기록을 변경하지 않는다.
- `archived`: 삭제 대신 목록과 추천에서 기본 제외하는 보관 상태.
- `draft_saved`만으로 `published`를 생성하거나 추론하지 않는다.

### 추천·분류 상태

- 오늘의 추천은 숫자 합산 점수가 아닌 우선순위 규칙과 이유 목록으로 정렬한다.
- 의도 분류는 `intent_version`, `intent`, `matched_markers`, `confidence`를 반환한다.
- 판정 근거가 없으면 `other` 또는 `unclassified`로 유지하며 LLM으로 자동 보정하지 않는다.

## Phase 3. 근거 브리프 FactPack

### 목표

### 구현 태스크

- [ ] `FactPack`과 `FactPackVersion`의 snapshot/draft 연결, 상태, selected evidence, warnings, created_at 계약을 정의한다.
- [ ] snapshot에서 질문, 검색 결과 metadata, 검색량, Trend, source 상태를 추출하는 로컬 builder를 구현한다.
- [ ] 근거 항목에 source type, source URL 또는 내부 ID, collected_at, from_cache, freshness, 사용 여부를 보존한다.
- [ ] `POST /v1/factpacks`, `GET /v1/factpacks/{id}`, version append API를 추가한다.
- [ ] Research Workspace에 근거 선택·제외·경고·승인 UI를 추가한다.
- [ ] Draft 생성 요청은 선택적으로 `factpack_id/version`을 받고 snapshot 소유권과 keyword 일치를 LLM 호출 전에 검증한다.
- [ ] LLM prompt에는 승인된 정규화 근거와 출처 표지만 포함하고 전체 provider 응답은 전달하지 않는다.
- [ ] 생성된 Draft lineage에 FactPack ID·version을 저장하고 상세 화면에서 근거로 돌아갈 수 있게 한다.

### 자체 테스트

- [ ] 없는 snapshot, 다른 keyword snapshot, empty/partial source, stale cache를 검증한다.
- [ ] FactPack 버전 append 시 과거 버전이 변경되지 않는지 확인한다.
- [ ] 미승인 FactPack과 소유권 불일치가 외부 LLM 호출 전에 차단되는지 확인한다.
- [ ] 선택하지 않은 본문·Secret·전체 payload가 prompt와 Extension storage에 포함되지 않는지 검사한다.
- [ ] skeleton 초안 경로도 동일 FactPack lineage를 보존하는지 확인한다.
