## 개발 목적
**기존 기능 축소 없이 독립 웹앱으로 전환하고, 사용자가 무엇을 입력하고 어떤 결과를 얻는지 명확한 화면을 제공한다.**
서버 실행이나 목업 표시를 완료로 보지 않는다. 확장이 없어도 실제 원고 작성·수정·저장·분석·성과 관리가 가능해야 한다. 현재 탭을 읽는 기능은 확장에 유지하고 웹 작업에 연결한다.

## 공통 진행 규칙
- 기능을 줄이지 않고 **배치와 이름을 바꾼다**. 기본 화면에서 접어 두더라도 명확한 이름과 접근 경로를 유지한다.
- 기존 확장은 전환 기간 내내 동작해야 한다. 웹과 확장은 같은 업무 로직·계산·API 계약을 사용한다.
- 선행 단계 자체 테스트 후 다음 단계로 진행한다. 단계별 결과·실패·수정·재검증을 이 문서에 남긴다.
- 모든 변경은 기존 dirty tree를 보존한다. 실패 테스트를 삭제하거나 기준을 낮추어 통과시키지 않는다.
- 운영 DB와 샘플 DB를 분리한다. 이 계획 작성만으로 서버·DB·설정·확장을 변경하지 않는다.
- API/정상 경로/화면 테스트/실계정 인수를 구분하고, 미검증 기능을 검증 완료로 표시하지 않는다.
- 아래 단계명은 **이번 웹앱 전환의 P0~P3**이며 기존 성과 구현 계획의 P0~P3와 별개다.

## 착수 전 기준과 전환 원칙
- 코드 기준: `main / b8d461e` 위의 미커밋 구현·수정 전체. 커밋 기준만 비교하면 최신 성과/작성 기능을 누락하므로 작업 트리 기준 목록도 동결한다.
- 현재 앱은 `apps/extension`과 `apps/local-core`다. 별도 웹앱은 아직 없다.
- 마지막 전체 검증 이력은 Python 267 + Extension 74 = 341건이다. 이번 문서 작성에서는 재실행하지 않았으며 구현 착수 시 다시 기준선을 확보한다.
- Settings의 `browser.storage`, 화면 이동의 `browser.tabs/runtime`, 현재 탭 수집을 분리해야 한다. 확장 HTML만 HTTP로 제공하거나 가짜 `chrome` 객체를 주입하는 방식은 사용하지 않는다.
- 일반 웹앱은 기존 API로 동작한다. 현재 탭 수집은 선택형 확장, SmartEditor 임시저장은 기존 별도 로그인 브라우저로 수행한다. 서로 다른 요구사항을 모두 “확장 필요”로 표시하지 않는다.

아래 신규 경로는 **예정 경로**다. 현재 존재한다고 가정하지 않는다.

| `python/publisher/*` | 기존 임시저장 엔진 유지. UI 변경 때문에 selector·저장 성공 기준을 느슨하게 하지 않음 |

- 공통 패키지는 위 책임 두 개만 둔다. 범용 디자인 시스템/플러그인 프레임워크를 새로 만들지 않는다.

- 외부 API 호출·provider 키·Codex 인증·DB 저장은 계속 Local Core 책임이다. 기존 API 경로와 데이터 schema를 불필요하게 변경하지 않는다.
- 웹/확장 원고·성과는 같은 서버 데이터를 사용한다. 기존 확장 설정을 Chrome 프로필 파일에서 읽어 자동 복제하지 않는다. 비밀값이 아닌 설정 이전은 사용자 확인 후 제공한다.
- 새 내부 URL에는 원고·Snapshot·근거·추천 ID 및 비민감 선택값만 넣는다. 본문/메모/token/provider 응답을 query에 넣지 않는다. 기존 deep link 호환은 의미 보존 테스트 후 처리한다.

## 최초 연결·샘플 검수·운영 경계
- 웹 인증은 초기 1회 **로컬 실행기에서 발급한 짧은 유효시간의 일회용 연결 코드 → HttpOnly 웹 세션**으로 설계한다. 긴 API 토큰을 일반 화면·URL·JS 번들·localStorage에 넣지 않는다.
- 코드 발급은 로컬 실행기 내부에서만 가능하게 한다. 비인증 HTTP 조회로 코드를 가져오는 endpoint는 금지한다. 소비 1회·만료·시도 제한·세션 만료/종료·SameSite 쿠키·정확한 Origin/Host 검사·상태 변경 요청의 CSRF 방어를 테스트한다.
- 기존 확장의 `X-Local-Token` 인증은 보존한다. loopback만 수신하고 public/LAN 노출이나 wildcard CORS를 추가하지 않는다. 외부 provider 설정 UI가 키를 평문으로 반환하지 않는다.
- 일반 웹앱과 샘플 검수는 별도 DB·설정·세션·포트로 격리한다. 샘플 모드는 모든 화면에 `샘플 데이터 / 외부 전송 안 함`을 표시하고 실제 모델/provider/Publisher를 **서버에서도 차단**한다.
- 쿠키는 포트만으로 격리되지 않는다. 실제/샘플의 쿠키 이름·서명 키·세션 대상 환경을 분리하고 서버가 다른 환경의 세션을 거부하도록 검증한다.
- 샘플은 실업무 기능의 대체물이 아니다. 같은 UI/API 응답 계약을 사용하는 fixture이며 실제 모드로 넘어가면 실제 DB를 사용한다. 샘플 정리는 운영 DB에 영향을 주지 않아야 한다.
- 실행기는 최신 웹 빌드·API 계약/계산 버전·port 소유 프로세스를 확인한다. 다른 프로젝트 프로세스를 종료하지 않고, DB 변경 전 백업하고 실패하면 무리하게 진행하지 않는다.
- 배포 시 오래된 HTML이 삭제된 asset을 참조하지 않도록 캐시 전략과 빌드 ID를 제공한다. 필요한 경우 재열기 안내를 하되 편집 중 내용을 날리는 강제 새로고침은 금지한다.
