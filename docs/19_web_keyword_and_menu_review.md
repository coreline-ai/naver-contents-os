# 키워드 찾기 · 기존 메뉴 · 앱 설정 검토

검토일: 2026-09-06 KST. 범위: 독립 웹앱 P2-A + 사용자 메뉴 혼동 해소.

## 확인된 문제와 수정

- 기존 웹 `키워드 찾기`에는 관심 키워드 목록만 연결돼 있었다. 기존 Research Workspace의 급상승·의도·맵·타깃·입찰·특화 도구는 웹에서 빠져 있었다.
- 현재는 `최신·급상승`을 기본 화면으로 사용한다. 입력이 없어도 이 컴퓨터에 저장된 조건별 최근 결과를 보여 준다. 조건별 최신 실행 8개 중 처음 3개 조건/각 4개 후보만 펼치며 나머지도 더 보기로 접근한다.
- 새 수집은 사용자가 실행한다. 일반·지역·쇼핑·뉴스, 최근 7일/이전 7일, 상승률, 뉴스 표본, 최신성 점수, 신뢰도·결측·수집 시각을 표시한다. 후보는 처음 8개, 전체 보기로 최대 20개를 확인한다.
- 입력 추천은 400ms 대기 후 최근 검색/SearchAd 연관어를 조회한다. 추천·결과 키워드는 클릭 즉시 재분석하며, 글쓰기는 같은 탭으로 주제만 전달한다. 자동 AI 생성·공개 발행은 하지 않는다.
- 앱 설정은 AI 준비 상태, API별 사용량, 블로그 ID·태그, 민감 키워드 판별 응답 없음 옵션, 로컬 세션 종료로 구분했다. 내부 환경변수 키 목록을 그대로 나열하지 않는다.

## 첨부 Research Workspace와 새 메뉴 대응

| 기존 메뉴 | 새 위치 |
|---|---|
| 오늘의 작업 | 글쓰기 → 오늘 이어서 할 일 |
| 콘텐츠 작업함 | 내 원고 → 저장된 원고 |
| 발행 콘텐츠 | 내 원고 → 공개 완료 기록 |
| 근거 브리프 | 글쓰기 → 근거와 플랜으로 쓰기 |
| 의도별 키워드 · 키워드 맵 | 키워드 찾기 → 키워드 분석 → 키워드 상세 도구 |
| 급상승 | 키워드 찾기 → 최신·급상승 |
| Watchlist | 키워드 찾기 → 관심 키워드 |
| 특화 분석 | 키워드 찾기 → 분야별 자료 |
| 광고 성과 상세 집계 | 성과 → 광고 계정 성과 (P2-B 후속 반영) |

모든 화면 상단의 **기존 Research Workspace 기능은 어디 있나요?** 안내에서 실제 위치로 이동한다. 기존 확장 화면이 자동으로 새 웹 디자인으로 바뀌는 것은 아니다.

## ‘실시간 인기어’와의 차이

연결된 [네이버 검색어 트렌드 API](https://developers.naver.com/docs/serviceapi/datalab/search/search.md)는 지정한 키워드 그룹의 일·주·월 **상대 추이**를 제공한다. 이 데이터만으로 전체 네이버의 공식 실시간 인기 검색어 순위를 제공한다고 주장할 수 없다.

- 최신 수집 시각과 검색 추이의 관측 기간은 다르다. 기본 비교는 전일까지 14일이다.
- 뉴스량은 최신 검색 결과에서 수집한 표본이며 전체 기사 발생량이 아니다. 표본 상한/뉴스 미수집을 함께 표시한다.
- 쇼핑은 클릭 추이이며 판매량이 아니다. 서로 다른 조건·모드의 최신성 점수를 전체 인기 순위로 합치지 않는다.
- 데이터가 없으면 ‘자료 없음/부족’, 이전 구간 0이면 ‘신규’로 표시한다. 결측을 0이나 임의의 상승률로 바꾸지 않는다.
- 범분야 실시간 인기 피드는 별도 데이터 제공처·수집 허용 범위·갱신 주기 계약이 필요하며 이번 구현에 포함하지 않았다.

## 설정의 의미

1. **글쓰기 AI:** 서버에 설정된 엔진·모델과 준비 상태. 상태 확인으로 글은 생성하지 않는다.
2. **블로그 ID·태그:** 이 브라우저에 자동 저장하는 기본값. 비밀번호/긴 API 토큰 입력란이 아니다. 확장/다른 브라우저와 자동 공유되지 않는다.
3. **API 사용량:** 네이버 검색, 검색 추이, 쇼핑 추이, SearchAd. 설정 존재와 실제 권한 검증을 구분한다. 키는 서버 `.env`에서 관리한다.
4. **앱 연결:** 로컬 원고 접근용 세션. 네이버 로그인 성공과는 별개다. 연결 종료가 원고 삭제를 뜻하지 않는다.
