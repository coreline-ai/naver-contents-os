## 개발 목적

현재의 단일 키워드 분석 흐름을 유지하면서 다음 기능을 추가한다.

- 입력 중 연관 키워드를 추천한다.
- 분석 결과의 `연관 키워드`를 입력창 바로 아래 상단 영역에서 먼저 보여준다.
- `급상승 키워드` 탭에서 최근 7일과 이전 7일의 상대 검색 추이를 비교한다.
- 검색 추이와 최근 뉴스 기사 표본을 결합한 설명 가능한 `최신성 점수`를 제공한다.
- 일반·지역·쇼핑·뉴스 모드를 지원한다.
- 추천 또는 급상승 키워드를 누르면 기존 분석 흐름으로 즉시 재분석한다.

## 전문가 검토 결론

1. NAVER 공식 API만으로는 전체 사용자를 대상으로 한 전역·실시간 인기 검색어 순위를 만들 수 없다. 따라서 기능명과 안내 문구는 `입력 주제 기반 급상승 후보`로 고정하고 `공식 실시간 인기순위가 아님`을 표시한다.
2. 입력 자동완성은 API 호출부터 시작하지 않는다. 확장 프로그램의 최근 선택 기록을 즉시 보여준 뒤, debounce가 끝난 경우에만 SearchAd 연관 키워드를 합친다.
3. 급상승 수집은 자동 배경 실행하지 않는다. 사용자가 `최신 수집`을 누른 경우에만 실행하며, 한 번의 수집은 외부 호출 최대 10회로 제한한다.
4. Search Trend `ratio`는 절대 검색량이 아니다. 같은 키워드의 같은 14일 시계열 안에서만 7일 평균 변화율을 계산하며, 서로 다른 요청의 ratio 자체를 검색량처럼 합산하거나 비교하지 않는다.
5. 뉴스 검색은 날짜 범위 전체 건수를 직접 반환하지 않는다. `sort=date`, 최대 100건 표본에서 최근 7일 기사 수를 계산하고 UI에는 `최근 7일 기사 표본(최대 100)`으로 정확히 표시한다.
6. 점수만 노출하지 않고 추세 점수·뉴스 점수·관측률·수집 시각·데이터 상태를 함께 반환한다. 일부 공급자가 실패하면 0으로 대체하지 않고 `부분 데이터` 또는 `계산 불가`로 표시한다.
7. 사이드패널에는 Top 8과 빠른 재분석만 두고, 20개 후보·세부 근거·분야 필터는 Research Workspace에 둔다.

## 문서 기반 제약 사항 / 결정 기록

### 데이터 창과 급상승 판정

- 기준 시간대는 `Asia/Seoul`이며 오늘의 미완료 데이터는 제외한다.
- `recent7`: 어제부터 7일, `previous7`: 그 이전 7일로 고정한다.
- Search Trend와 Shopping Insight provider는 `start_date`, `end_date`, `time_unit=date`를 명시적으로 받을 수 있게 확장한다.
- 각 구간에 6일 이상, 전체 14일 중 12일 이상 관측된 경우에만 수치 비교를 허용한다. 누락일은 임의로 0을 채우지 않는다.
- `previous7_avg > 0`이면 `growth_rate = (recent7_avg - previous7_avg) / previous7_avg * 100`으로 계산한다.
- 이전 평균이 0이고 최근 평균이 양수이면 퍼센트를 무한대로 만들지 않고 `direction=new`, `growth_rate=null`로 반환한다.
- 방향은 `new | rising | steady | falling | insufficient`이며 기본 경계는 상승 `>= +10%`, 하락 `<= -10%`, 나머지는 보합이다.
- SearchAd 월간 검색량은 후보 정렬 보조·신뢰도 설명에만 사용하고, `< 10` 마스킹 값을 0으로 변환하지 않는다.

### 최신성 점수 v1

- 점수 범위는 0~100이며 `score_version=freshness-v1`을 저장한다.
- 일반·지역 모드 가중치: 검색 추세 65%, 뉴스 35%.
- 쇼핑 모드 가중치: 쇼핑 클릭 추세 70%, 뉴스 30%.
- 뉴스 모드 가중치: 검색 추세 35%, 뉴스 65%.
- 일반 상승의 `trend_score`는 `clamp(max(growth_rate, 0) / 2, 0, 100)`으로 계산한다. `new`는 `clamp(recent7_avg, 0, 100) * (recent_observed_days / 7)`로 계산한다.
- `news_volume_score = 100 * ln(1 + news_7d_sample_count) / ln(101)`, `news_recency_score = max(0, 100 * (1 - latest_age_hours / 168))`, `news_score = volume 70% + recency 30%`로 계산한다.
- News는 `sort=date&display=100`의 제목·링크·`pubDate`만 사용하고 `originallink` 우선으로 중복을 제거한다. 표본 100건 모두가 7일 이내이면 `sample_capped=true`로 표시한다.
- 추세 관측 기준과 News 요청이 모두 성공한 후보만 최종 점수를 낸다. 하나라도 부족하면 `freshness_score=null`과 원인 코드를 반환하고 사용 가능한 구성 점수만 별도 표시한다.
- `confidence`는 14/14 관측·표본 미포화·검색량 비마스킹·`new` 아님이면 `high`, 12~13일 관측 또는 표본 포화이면 `medium`, `new` 또는 검색량 마스킹이면 `low`, 계산 불가이면 `unavailable`로 고정한다.
- 응답은 원시 평균, 변화율, 구성 점수, 관측일 수, 표본 수, 최신 기사 시각, 점수 버전, 데이터 상태를 포함하여 계산을 재현할 수 있어야 한다.

### 모드별 의미

| 모드 | 필수 입력 | 후보/추세 | 화면 표현 |
|---|---|---|---|
| 일반 | 주제 seed | SearchAd 후보 + Search Trend | 주제 연관 급상승 후보 |
| 지역 | 지역명 필수, 주제 선택 | `지역명 + 주제` 후보 + Search Trend | 해당 지역 문맥의 연관 급상승 후보 |
| 쇼핑 | 주제 seed, Shopping category code | SearchAd 후보 + Shopping Insight | 쇼핑 클릭 급상승 후보 |
| 뉴스 | 뉴스 주제 seed | SearchAd 후보 + Search Trend + News | 주제 관련 뉴스 최신 후보 |

- seed 없이 전역 목록을 생성하지 않는다. 일반·쇼핑·뉴스는 seed가 필수이며, 지역은 지역명이 필수이고 seed를 생략하면 지역명 자체를 유효 seed로 사용한다. 쇼핑은 category code도 필수다.
- 지역 모드는 전국 지역 순위를 의미하지 않으며, Local Search 장소 결과를 최신성 점수에 합산하지 않는다.
- 모드별 가중치가 다르므로 서로 다른 모드의 점수를 직접 비교하지 않는다.

### 호출 예산과 캐시

- 추천 입력: 한글/CJK 2자 또는 그 외 3자 이상, 700ms debounce, 표시 최대 8개, 단일 in-flight 요청, 동일 정규화 prefix 요청 합치기.
- 추천 SearchAd 결과 TTL은 기존 24시간을 유지한다. 429 또는 공급자 실패 시 최근 local 항목은 유지하고 무한 재시도하지 않는다.
- 급상승 1회 후보는 SearchAd 월간 검색량 기준 최대 20개다.
- 일반·지역·뉴스: SearchAd 1회 + Search Trend 5개 그룹씩 최대 4회 + 상위 추세 후보 News 최대 5회 = 최대 10회.
- 쇼핑: SearchAd 1회 + Shopping Insight 5개씩 최대 4회 + News 최대 5회 = 최대 10회.
- 최신 News 전용 캐시는 15분, 일 단위 Trend/Shopping 캐시는 6시간으로 분리하고 `force_refresh`는 사용자의 명시적 `최신 수집`에만 연결한다.
- UI는 실행 전 예상 외부 호출 수와 마지막 수집 시각을 표시한다. 자동완성은 강제 새로고침을 절대 사용하지 않는다.

## API·계약 초안

### `POST /v1/keywords/suggest`

- 요청: `{ query, limit: 8 }`
- 응답 항목: `keyword`, `source`, `monthly_searches`, `volume_masked`, `competition`, `from_cache`, `collected_at`
- 응답 상태: `ok | partial | unconfigured | rate_limited | upstream_error`
- 서버에서도 길이·limit·중복 prefix·응답 개수를 제한한다.

### `POST /v1/research/rising`

- 요청: `seed?`, `mode`, `region?`, `category?`, `candidate_limit<=20`, `force_refresh=false`
- 응답: `run_id`, `mode`, `comparison_window`, `estimated_calls`, `actual_calls`, `score_version`, `collected_at`, `data_status`, `candidates[]`
- 후보 항목: `keyword`, `direction`, `recent7_avg`, `previous7_avg`, `growth_rate`, `trend_score`, `news_7d_sample_count`, `sample_capped`, `latest_news_at`, `news_score`, `freshness_score`, `confidence`, `coverage`, `monthly_searches`, `volume_masked`, `components`, `source_meta`
- `data_status`는 공급자별 상태를 유지하고 부분 실패를 HTTP 500 하나로 뭉개지 않는다. 요청 검증 실패만 4xx로 처리한다.

### `GET /v1/research/rising/latest`

- query: `mode`, `seed?`, `region?`, `category?`
- 같은 정규화 조건의 마지막 성공 `DiscoveryRun`을 반환하고 없으면 404가 아니라 `run=null`을 반환한다.

### 저장

- `DiscoveryRun` 테이블에 seed·mode·비교 기간·요청 파라미터·정규화 결과 JSON·점수 버전·수집 시각을 저장한다.
- API secret, 인증 header, 기사 전문, provider 원문 전체는 저장하지 않는다.
- 같은 수집 요청의 provider 캐시는 `api_cache`를 재사용하고, UI 재진입은 마지막 성공 run을 먼저 표시한다.

## GUI 구성 제안

### 사이드패널

```text
┌ 키워드 입력 __________________ [분석] ┐
│  입력 추천 dropdown: 최근 | SearchAd  │
├ [연관 키워드] [급상승 키워드]         ┤
│  Top 8 chip + 검색량/상승률            │
│  [최신 수집] 마지막 수집 22:10         │
└ keyword click → 기존 beginAnalysis 1회 ┘
   점수 / 시장 지형 / 플랜 / 초안 ...
```

- 입력 추천은 키보드 위·아래·Enter·Esc와 `aria-combobox`를 지원한다.
- 분석 후 연관 키워드 Top 8을 점수 카드보다 위로 이동한다. 기존 최대 50개 상세 목록은 Keyword 영역 또는 Workspace에 유지한다.
- 추천/급상승 클릭은 공통 `selectKeywordAndAnalyze(keyword)` 하나로 통합하고 중복 API 호출을 막는다.

### Research Workspace

```text
[키워드 맵] [급상승] [Watchlist] [특화 분석] [광고 성과]

급상승  [일반] [지역] [쇼핑] [뉴스]
주제 ______  지역 ______  카테고리 ______  [최신 수집 · 최대 10회]

키워드 | 방향 | 최근7일 | 이전7일 | 상승률 | 뉴스표본 | 최신성 | 신뢰도
```

- 기본 정렬은 계산 가능한 `최신성 점수` 내림차순, 동점은 상승률·월간 검색량 순이다.
- `new`, `insufficient`, 마스킹 검색량, 부분 데이터는 색뿐 아니라 텍스트·아이콘으로 구분한다.
- 후보 클릭은 즉시 분석을 시작하며, 재클릭·빠른 연속 클릭은 최신 요청 한 건만 유효하게 한다.
