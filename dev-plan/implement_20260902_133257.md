## 개발 목적

NAVER API HUB의 `Client ID/Client Secret`과 SearchAd의 `API Key/Secret Key/Customer ID`만으로 현재 단일 키워드 분석을 키워드 포트폴리오 연구 기능으로 확장한다. 기존 사이드패널의 빠른 분석→플랜→초안 흐름은 유지하고, 그래프·다중 비교·Watchlist처럼 정보 밀도가 높은 기능은 확장 프로그램 내부 전체화면 `Research Workspace`로 분리한다.

## 개발 범위

- 검색 전 오타 교정·민감 키워드 판별과 명시적 사용자 선택을 추가한다.
- SearchAd 연관어를 제한된 2단계 그래프로 확장하고 검색량·경쟁·Trend 근거를 노드에 결합한다.
- SearchAd Estimate 조회로 유료 광고 관점의 상업성 지표를 별도 표시한다.
- Search Trend의 기기·성별·연령 필터로 세그먼트별 상대 추세 패턴을 비교한다.
- 사용자가 선택한 키워드만 수동 갱신하는 Watchlist를 추가한다.
- 지역 검색, Shopping Insight, 이미지 검색을 명시적 특화 모드로 제공한다.
- SearchAd 계정에 성과 데이터가 있을 때 조회 전용으로 콘텐츠 공백 후보를 제안한다.
- 사이드패널과 Research Workspace의 로딩·부분 성공·결측·캐시·quota 상태를 같은 규칙으로 표시한다.

## 문서 기반 제약 사항 / 결정 기록

- API Secret은 Local Core에만 두고 Extension에는 Local Core token과 비민감 UI 상태만 저장한다.
- 모든 신규 SearchAd 기능은 조회 전용 endpoint만 허용한다. provider에 mutation method를 추가하지 않는다.
- HUB 검색 응답은 `Content-Type`과 무관하게 JSON 본문 파싱을 시도한다.
- SearchAd `/keywordstool` hint는 기존 규칙대로 공백을 제거하고 사용자 표시값은 원문을 유지한다.
- Search Trend `ratio`는 요청 범위의 상대 추세다. 서로 다른 성별·연령 요청 간 절대 규모 비교나 “주요 고객 비중” 판정에 사용하지 않는다.
- 그래프 확장은 기본 `seed 1 + 1차 30개 + 2차 seed 5개`, 최종 node 80개 이하로 제한한다. 외부 전송 횟수·cap은 설정과 테스트로 고정한다.
- Watchlist는 사용자가 누른 `선택 갱신` 또는 `전체 갱신`만 제공하고 자동 갱신은 하지 않는다.
- 지역·쇼핑·이미지는 자동 의도 추정이 아니라 사용자가 고르는 특화 모드로 시작한다.
- 이미지 결과는 출처 링크·크기·참고용 썸네일만 표시하며 재사용 권리를 보장하지 않는다는 안내를 고정한다.
- Cytoscape.js의 MIT 라이선스를 확인했다. 안정화·번들 최소화를 위해 신규 의존성 대신 keyboard 접근성을 포함한 결정적 SVG renderer를 사용하고 Python 분석에는 현재의 cluster 로직을 재사용한다.

## GUI 구성 제안

### 1. 사이드패널: 빠른 결정과 작성 흐름

사이드패널은 약 430px 폭을 기준으로 유지한다. 그래프를 축소해서 넣지 않고 요약과 선택 action만 제공한다.

```text
┌──────────────────────────────────────┐
│ Naver Content OS          ● 연결됨  설정 │
├──────────────────────────────────────┤
│ [네이버 블로그____________] [분석]      │
│ 교정 제안: 네이버 블로그 [사용] [원문]   │
│ [일반] [지역] [쇼핑] [이미지]            │
├──────────────────────────────────────┤
│ [분석] [플랜] [초안]                    │
│                                      │
│ 분석 > [개요] [키워드] [타깃] [상업성]   │
│ ┌ Score 78.4  신뢰도 높음 ─────────┐ │
│ │ 검색량 · Trend · 문서 경쟁 요약     │ │
│ └──────────────────────────────────┘ │
│ 상승 키워드 3 · 상업성 높음 4           │
│ [Research Workspace 전체화면 열기]      │
│                                      │
│ 키워드 Top 5 / 세그먼트 요약 / 입찰 요약 │
├──────────────────────────────────────┤
│ 플랜 15편 → AI 초안 → 버전 → 임시저장    │
└──────────────────────────────────────┘
```

- 상단 keyword·연결 상태·설정은 모든 화면에서 유지한다.
- 1차 탭은 `분석 / 플랜 / 초안`으로 기존 긴 스크롤을 분리한다.
- 분석 내부 탭은 `개요 / 키워드 / 타깃 / 상업성`으로 제한한다.
- 카드마다 `live`, `cache`, `부분 데이터`, `미설정`, `quota 경고`, `수집 시각` chip을 같은 위치에 표시한다.
- 그래프 node 선택, Watchlist 관리, 다중 비교는 전체화면으로 이동한다.

### 2. Research Workspace: 그래프·비교·운영

WXT의 별도 extension page `research.html`을 추가하고 URL에는 `snapshot_id` 또는 `keyword`만 전달한다. Secret·본문·전체 API 응답은 URL이나 Extension storage에 저장하지 않는다.

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ Research Workspace | 네이버 블로그 | snapshot #42 | 13:30 수집 | [새로고침] │
├───────────────┬──────────────────────────────────────────┬─────────────────┤
│ 키워드 맵      │                                          │ 선택 노드        │
│ Watchlist      │            Opportunity Graph             │ 블로그 글쓰기     │
│ 특화 분석      │      ○────○────●────○                    │ 검색량 6,290     │
│ 광고 성과      │           │     └──○                      │ Trend +12%*      │
│               │                                          │ 경쟁 중간        │
│ 필터           │  크기=검색량  색=cluster  테두리=상태       │ 상업성 높음       │
│ 검색량         │                                          │ [분석] [Watch]   │
│ Trend          │                                          │ [플랜 후보]      │
│ 경쟁도         │                                          │                 │
├───────────────┴──────────────────────────────────────────┴─────────────────┤
│ [표] [상대 Trend] [타깃 패턴] [입찰 추정] [검색 근거]                      │
└────────────────────────────────────────────────────────────────────────────┘
```

- 왼쪽은 화면 이동과 filter, 가운데는 주 시각화, 오른쪽은 선택 node inspector로 고정한다.
- node 크기는 검색량, 색은 cluster, 테두리는 수집 상태, badge는 Trend·상업성으로 표현한다.
- 색만으로 상태를 전달하지 않고 아이콘·텍스트를 함께 사용한다.
- 하단 탭은 그래프와 동일 snapshot의 표·Trend·근거를 보여주어 시각화 오판을 검증할 수 있게 한다.
- 1024px 미만에서는 오른쪽 inspector를 drawer로 전환하고, 사이드패널에서는 전체화면 링크만 노출한다.

### 3. 핵심 상태 UX

| 상태 | GUI 처리 |
|---|---|
| API 미설정 | 빈 차트 대신 필요한 환경변수 이름과 설정 action 표시 |
| 일부 provider 실패 | 성공한 카드 유지, 실패 source만 경고와 재시도 표시 |
| cache hit | `cache` chip과 원 수집 시각 표시 |
| quota 80% 이상 | amber usage bar, 예상 추가 호출 수 확인 후 실행 |
| quota 초과 | action 비활성화와 다음 가능 시점/설정 한도 표시 |
| `< 10`·null | `0`으로 변환하지 않고 `10 미만`·`결측` 표시 |
| Trend | 모든 차트에 `상대지수, 절대 검색량 아님` 고정 문구 표시 |
| Watchlist 비교 불가 | 동일 기간·단위·segment snapshot이 아니면 delta 계산 금지 |
